일본 여행 중 상품 바코드(JAN)를 스캔해 일본 상품을 조회·번역하고 위시리스트로 저장하는 앱인토스 미니앱이다. 본 문서는 시스템 아키텍처 다이어그램(아이콘 버전)을 기준으로 작성한다.

## 1. 개요

클라이언트(React Native 미니앱)가 백엔드(프록시 서버)를 호출하고, 백엔드가 외부 서비스와 데이터베이스(Supabase)를 연결하는 구조다. 외부 API 키와 비즈니스 로직은 백엔드에 둔다. 클라이언트는 백엔드만 호출하며 데이터베이스나 외부 API에 직접 접근하지 않는다.

## 2. 구성 요소

### 2.1 클라이언트 — React Native 미니앱 (앱인토스 · TDS)

토스 미니앱 플랫폼(앱인토스)에서 동작하며 TDS를 사용한다. 화면은 로그인, 메인, 바코드 스캔, 상품 촬영(조회 실패 시), 결과, 저장 목록으로 구성된다. 백엔드와는 REST API(HTTPS)로만 통신한다.

### 2.2 백엔드 — 프록시 서버

비즈니스 로직과 외부 API 키를 보관하고, 메모리 캐시(JAN 키)로 동일 바코드의 재호출을 줄인다. 클라이언트와는 REST로, Supabase와는 직접 연결로 통신한다.

### 2.3 외부 서비스

| 서비스 | 용도 |
| --- | --- |
| 토스 SDK | 로그인 및 사용자 식별(toss_user_key) |
| 라쿠텐 Product Search | productCode(JAN) 조회, keyword 조회 |
| 번역 API | 상품명·브랜드 일→한 번역 |
| Gemini API | 사진에서 상품정보 추출(상품명·브랜드·검색 키워드) |

### 2.4 데이터 — Supabase (PostgreSQL · RLS)

테이블은 users, saved_products, scan_history 세 개다. Row Level Security로 사용자별 접근을 제어하며, users는 토스 식별자(toss_user_key)와 연동된다.

## 3. 핵심 흐름

### 3.1 로그인

사용자가 RN 미니앱에서 토스 SDK로 로그인하면, 백엔드가 인증을 검증하고 세션을 생성한다.

### 3.2 상품 조회 (폴백 순서)

1. 백엔드 메모리 캐시(JAN)를 확인한다.
2. 라쿠텐 productCode(JAN)로 조회한다. 성공하면 lookup_type은 barcode다.
3. 실패하면 사용자가 상품을 촬영하고, Gemini가 상품정보를 추출한 뒤 번역 API로 일→한 번역하고, 라쿠텐 keyword로 재조회한다. 성공하면 lookup_type은 keyword다.
4. 그래도 실패하면 Gemini 추출값을 그대로 사용하며 lookup_type은 ai다.

### 3.3 저장 / 이력

저장 시 saved_products에 상품 정보를 스냅샷으로 보관하고 UNIQUE(user_id, barcode)를 둔다. 스캔 이력은 scan_history에 1 스캔당 1 row로 남기고, 폴백으로 결과가 바뀌면 해당 row를 UPDATE하며 found를 기록한다.

## 4. 설계 원칙 / 보안

- 키와 로직을 백엔드에 두어 클라이언트 키 노출을 막는다.
- RLS로 사용자 본인 데이터만 접근하게 한다.
- 메모리 캐시로 동일 바코드의 외부 호출과 AI 토큰을 줄인다.

## 5. 설계 결정 배경

근거가 정리된 항목은 다음과 같다.

- 백엔드 프록시 구조: 외부 API 키 노출을 막고, 레이트리밋·캐시·폴백을 한곳에서 통제하기 위함이다.
- 번역 분리: 상품명·브랜드 번역을 AI 대신 번역 API로 처리해 AI 토큰을 절감한다(회의 결정).
- 메모리 캐시(JAN): 동일 바코드 재호출 시 외부 API와 토큰을 절약한다.

## 6. 확인 필요 항목

자료만으로 확정하기 어려워 답변이 필요한 부분이다.

- 백엔드 구현 스택(Node.js 등) 확정 여부. 문서에는 "프록시 서버"로만 표기된다.
- 데이터 스키마 기준: 본 다이어그램의 3테이블 스냅샷 방식과 테이블 정의서(xlsx)의 정규화 v2(community_products + 조인)가 다르다.
- lookup_type 코드값: API 문서(barcode/keyword/ai)와 비즈니스 로직 문서(direct/retry/cache/ai_vision)가 다르다.
- 번역 API 제공자: Papago / DeepL.
- 토스 인증 검증의 실제 방식: 토스 서버 토큰 검증인지, 클라이언트가 보낸 toss_user_key 신뢰인지.
- Gemini 직접 이미지 분석 폴백 유지 여부.

## 7. 범위 외

깃, CI/CD, 호스팅·배포 인프라, DNS 등 운영 인프라는 자료에 근거가 없어 본 문서에서 다루지 않는다.
